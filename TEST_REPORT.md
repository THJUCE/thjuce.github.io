# Отчёт о тестировании OneDash Telegram Bot

## Что проверено

1. Авторизация доступа: сценарий разрешённого и неразрешённого пользователя покрыт middleware и unit-тестами на уровне логики.
2. OneDash API client: успешные ответы, `type=false`, rate limit `429`, формирование payload для `create_vps`.
3. Внутренние сервисы: TTL-кэш, защита от двойного нажатия, вычисление цены и отображение ОС.
4. FSM-сценарии и inline-flow проверены локально статическим прогоном кода и импортом модулей.

## Как запускались тесты

```bash
python -m unittest discover -s tests -v
```

## Результат

- Все unit-тесты проходят локально.
- Обработаны сценарии ошибок API, таймаутов и повторных запросов.
- Для боевых сценариев `create/reinstall/clone/change tariff/top-up` предусмотрено явное подтверждение и cooldown-защита.

## Ограничения текущей проверки

- Дорогие и разрушающие действия не выполнялись на реальном аккаунте автоматически, чтобы не списывать баланс и не повредить существующие VPS.
- Отдельно перед продакшн-деплоем нужно вручную проверить реальные операции на аккаунте с включённым IP whitelist для API-ключа.
